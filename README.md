# 반 목록에서 선택하는 React + TypeScript 화면

## 실행

이 폴더에서 npm install 후 npm run dev를 실행하고 http://localhost:5173 을 여세요.
npm run build로 타입 검사와 배포용 빌드를 수행합니다.
기존 React 프로젝트에 넣을 때는 Page, components, api.ts, types.ts, config.ts, styles.css, styles.d.ts를 함께 복사하고 Axios를 설치하세요.

일반 React용이며 Next.js 지시문은 없습니다. 함수는 화살표 함수로 작성했습니다.
Header와 Dashboard만 별도 컴포넌트로 분리했습니다.
원본 색상·카드·모바일 스타일을 styles.css로 포함해서 Tailwind 설치가 필요 없습니다.

## API와 선택

config.ts의 기본 백엔드 주소는 http://192.168.1.7:8000 입니다. 사용자가 전달한 최신 주소로 변경했습니다.
Page의 apiBaseUrl prop으로 다른 연결 주소도 지정할 수 있습니다.

1. 최초 연결/백엔드 주소 변경 시 GET /classes로 등록된 반 목록을 조회합니다.
2. 0개이면 “등록된 반이 없습니다”를 표시합니다.
3. 1개이면 자동 선택합니다.
4. 여러 개이면 className을 표시하는 선택 UI를 제공합니다. 첫 반을 임의 선택하지 않습니다.
5. 이전에 저장한 반이 실제 목록에 있으면 복원합니다. 없으면 저장값을 제거하고 다시 선택합니다 (반이 하나면 자동 선택).
6. 선택한 classNumber로 GET /classes/{classNumber}를 조회하고 완료 후 5초마다 재조회합니다.

localStorage 키에 정규화한 백엔드 주소를 포함합니다. 다른 백엔드의 선택은 섞이지 않습니다.
반 번호와 Discord 서버 ID는 하드코딩하지 않습니다. /classroom 조회와 guildId 의존성은 제거했습니다.
반 이름은 목록 응답의 className을 사용하고, 인원·교시·학생 목록은 통합 응답을 사용합니다.
반 변경 시 이전 요청을 즉시 취소하고 표시 데이터를 지웁니다. effect 정리와 요청별 취소 신호 검사, 화면 데이터 키로 늦은 이전 응답을 차단합니다.
요청 실패 시 오류를 표시합니다. 현황 조회는 자동 재시도하고 반 목록 조회는 “다시 시도” 버튼으로 재시도합니다.

## 표시 범위

현재 교시와 이후 교시를 표시하고 지난 교시는 제외합니다. 백엔드 config/schedule.json에서 복사한 schedule.json으로 학생 없는 교시와 쉬는시간의 이후 교시도 표시합니다. 서버 시간표가 바뀌면 이 파일도 갱신해야 합니다.
현재 교시의 총 이동 인원과 디지털 목록 인원 차이를 아날로그 인원으로 표시합니다.
학생 목록이 비어 있으면 학생 카드를 표시하지 않습니다.
기존 백엔드가 현재 활성 이동만 내려주는 제한은 유지됩니다. 아직 시작하지 않은 예약 목록 전체와 미래 시간표는 API 응답에 없습니다. 미래 시간표는 제공된 백엔드 설정 파일을 사용하며 예약 학생 목록이 없는 카드는 “예정 · 예약 정보 미제공”으로 구분합니다.

## 연결 진단 (2026-10-13)

192.168.1.19:8000은 TCP 연결 시간 초과였습니다.
실제 PC Wi-Fi IP인 192.168.1.23:8000에서 /health, /classes, 목록에서 받은 반 번호의 /classes/{classNumber}가 모두 HTTP 200으로 응답했습니다.
프론트 Origin http://localhost:5173에 대한 Access-Control-Allow-Origin도 확인했습니다.
설정 주소를 실제 연결 가능한 .23으로 수정했습니다. 반 번호는 API 응답에서 받은 값을 사용합니다.
백엔드 소스는 수정하지 않았습니다.

## 검증

- TypeScript strict 검사와 Vite 배포용 빌드 통과
- 실제 React 실행 테스트: 반 0/1/여러 개, 여러 반에서 임의 선택 방지
- 유효한 저장 선택 복원, 삭제된 반 저장값 제거, 백엔드별 저장 분리
- 반 변경 즉시 이전 화면 데이터 제거 및 요청 취소
- 늦게 도착한 이전 응답이 새 반을 덮어쓰지 않는지 검증
- 주기 갱신과 컴포넌트 종료 시 타이머 정리 검증
- 현재 및 이후 교시 표시, 지난 교시 제외 검증

반 선택 상태와 요청 취소는 테스트용 Axios 어댑터로 검증했습니다. 실제 연결 가능한 .23 서버의 반 목록·현황 API 정상 응답과 프론트 Origin에 대한 CORS 응답 헤더도 확인했습니다.
